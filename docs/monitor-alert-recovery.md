# 运行告警与申请验证恢复

2026-10-24 截图显示网络超时和队列失败告警在同一分钟重复发送。查询发现 API 当前可用、Webhook 待接收为 0，AI 群一项申请拒绝因网络超时耗尽 6 次重试。

## 本次修复

- 告警发送前按事件与接收人持久占位，合并重复所有者 ID；成功冷却 30 分钟，失败保留 60 秒退避。部分接收人失败时不重发给已经成功的人，尊重旧版本冷却记录。
- 相同事件的异常、恢复串行更新，不让早先的网络请求覆盖后来的状态；已恢复事件更新详情；未向用户发过异常的短暂波动不额外发恢复通知。
- Telegram 可重试探测失败、权限读取失败、队列状态读取失败，需持续至少 5 分钟并有两次相隔至少 1 分钟的观察才报警。401 等明确不可重试错误，以及明确查到删消息/封禁权限缺失，仍立即提示。仍保留两次只读探测；不立即重试 429。
- Telegram API 已恢复时，监控检查各群失败的入群申请拒绝任务。仅在 24 小时内、失败后至少 15 分钟、相同 request 验证仍超时、错误为网络超时/无效上游响应时尝试恢复。只读核对当前成员状态，每个任务最多两轮，间隔至少 15 分钟；保留原始创建时间与操作进度。
- 已手动通过、新验证覆盖的旧任务取消；已入群成员取消旧申请拒绝并清理对应验证记录。不自动重放封禁、不绕过权限失败、不处理失效/超龄任务。确认后只重新排队，沿用原任务执行前的验证状态校验。
- 总览不再仅因七天内存在历史失败或正常重试退避就显示异常，依据最近一小时失败、积压超过五分钟及当前权限判定；失败列表与历史记录仍保留。

## 验证

npm ci、npm run check、npm test（203 项通过）。专项覆盖并发告警、重建对象占位、部分接收人失败、恢复更新顺序、网络观察窗口，以及申请拒绝恢复的各种边界。

## 后续优先级

1. 失败任务中心：显示当前仍需处理的原因、可安全重试/取消/人工处理，批量操作只处理明确安全的类别。
2. 广告判定质量：把用户确认的漏拦与误封变成固定回归样本；规则修改先回放，展示命中证据及来源，降低后续改规则反复伤及正常讨论的风险。
3. 真实权限与用途：频道仅推送、群管理、已退出群分别检查；历史模拟群和旧异常保留归档但不干扰当前健康总览，批量显示缺什么权限。
4. 资金提醒可观测性：独立显示 Waffo 最后收到、验签通过、入队、TG 已发/失败状态，提供明确测试标记，确认一次真实收款端到端投递。不要将单独 sendMessage 测试当作支付回调验收。
5. 备份恢复验收：现有自动备份加定期结构校验和隔离环境恢复演练，记录最近一次成功恢复测试时间；不在生产群自动做封禁/解封演练。

本补丁不启用 DMIT 监控、不新增定时自动化、不改变广告处理政策、不改订单机器人配置。需审核合并并得到上线授权后部署。
