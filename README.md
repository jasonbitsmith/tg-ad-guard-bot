## 默认行为

- 广告命中即删消息并永久封禁账号，不发送群内警告、不累计警告、不自动禁言；请只将明确禁止的广告词加入本群词库。
- 未命中广告规则的低风险内容仅记录。
- 同一短文由多个账号重复发布也会触发群级刷屏处理；频道身份的广告无法定位具体个人，只删除对应消息。
- 不覆盖管理员设置的已有用户限制；管理员、所有者和白名单用户不参与自动处罚。
- 警告在最近一次违规 24 小时后过期；刷屏窗口为 60 秒，相同内容 3 次或总消息 8 条触发处理。
- 词库按群独立，作为直接删除黑名单。首次使用时复制原 KV 词库，之后本群修改不会影响其他群。
- 欢迎语和群规按群独立设置；新成员加入时合并发送。欢迎语支持 `{name}` 和 `{group}` 占位符。
- 域名黑名单命中会直接触发处理；白名单只取消“包含链接”的基础加分，不会绕过其他广告信号。名单会匹配子域名。
- 后台显示近 30 天的关键词命中次数。只统计 v2.1.0 之后产生的新记录。
- 保留群内自动通知关闭的习惯，处理结果在后台查询；管理员主动发出的命令会得到回复。
- 不回溯封禁名单，不自动解除既有封禁，不恢复已删除消息。

## DMIT 补货雷达

- 使用 DMIT 官方价格页作为来源，识别产品代码、库存文字和官方购买链接；页面读取失败或产品结构无法识别时不会把它当作缺货，也不会覆盖既有库存状态。
- 每个产品首次发现时只记录状态，避免上线时把现有在售产品全部推送。后续只有“无货 → 有货”才通知频道。
- 通知包含产品、区域、线路、配置、流量/带宽、价格和“立即抢购”按钮。购买按钮把 `aff=16962` 加入该产品的原始 DMIT 链接。
- 管理后台“运行自检”接口会返回最近一次读取状态。DMIT 官网若启用安全验证导致 Cloudflare Worker 收到 403，状态会显示“读取失败”；这不是缺货，需要提供一个允许服务器访问的官方数据来源后才能做到实时监控。

## 管理指令

`/help` 查看说明；`/status` 检查策略及机器人权限。

`/addword 词`、`/removeword 词`、`/listwords` 只修改或查看本群词库。

以下指令回复用户消息，或附带数字用户 ID：

- `/warnings`：查看警告与白名单状态。
- `/clearwarn`：清除警告和刷屏计数。
- `/allow`、`/unallow`：加入、移出本群白名单。
- `/unmute`：按群默认权限解除限制。
- `/unban`：允许被封用户重新加入；不会踢出已在群的用户。
- `/ban`、`/kick`：管理员手动封禁、移出。要求操作者是机器人所有者、群主或具有限制成员权限的管理员。这些操作仍可能删除用户历史消息。

后台沿用原 `ADMIN_PASSWORD`，改为 8 小时 HttpOnly/Secure/SameSite 会话。退出会使会话失效，修改密码也会使旧会话失效。每 IP 15 分钟最多 10 次登录尝试。打开新版后台会清除旧版保存在 localStorage 中的密码。

## 可靠性与保留时间

每个群一个 SQLite Durable Object。Webhook 必须通过路径和 Telegram 请求头验证，事件持久化后才返回成功。重复 update_id 保留 7 天去重。临时错误与 Telegram 429 最多尝试 6 次，尊重 retry_after。处理步骤分别记录完成状态，重试不重复计警告；失败保留实际已完成的步骤。

Telegram 与 Cloudflare 之间没有分布式事务：在 Telegram 已完成操作、但本地还没保存结果的极短崩溃窗口，外部操作仍可能重复；自动处理使用重复安全的删除、固定截止时间禁言，无法宣称严格 exactly-once。管理员命令回复在这种窗口也可能重复发送。

任务用持久化 alarm 调度，正常情况下约 200ms 后开始。失败重试可能延迟，后台显示 pending/failed。失败任务不会无止境重试，需要管理员查看原因后手动处理。

新版记录保留 30 天，SQL 分页查询。旧 KV 日志仍可通过后台“旧版记录”查看，沿用其原有 TTL；没有删除或全量搬迁历史数据。正常任务结束后清除原始消息载荷，日志仅保留最多 300 字消息摘要。

## 备份与回滚

`backups/pre-fix-worker.js` 是修改前线上代码；`backups/pre-fix-settings.json` 保存原配置和部署版本信息，不包含密钥值。

此次增加了 Durable Object 类迁移，不应直接假设可以通过旧版本 ID 一键回滚。回退旧业务代码时必须保留 `GuardState` 类及绑定，停止其 alarm 任务，保留已写入的数据，并保留现有密钥；`backups/rollback-worker.js` 已提供这种回退构建。回退上传不包含新增或删除类的迁移。优先修复后向前部署，避免恢复旧版误封策略。

本次未新增入群验证码、AI/OCR、摘要或定时群公告；这些属于后续扩展，不影响本轮修正。


### 运行可靠性与样本审核

- 管理员回复广告发送 `/spam`：删除原消息、永久封禁发送者并删除命令；广告文字或图片指纹进入全局待审核样本。本群手动指令不自动联防，既有自动广告联防保持生效。
- 后台样本支持审核启用、误报停用和独立文字/域名测试。待审核和停用样本不参与处罚；停用样本不会自动解除过去的封禁，可使用 `/unban` 纠错。
- 分段广告只组合同账号同群最近三分钟最多五条文本，不读取引用内容；须命中既有明确广告组合规则。
- 后台审查进入持久队列。失败任务可以手动重试，已完成步骤不会重复执行；记录显示真实结果。
- 日报只统计成功处罚，并增加执行失败、重试、OCR 失败、队列等待、处理延迟和 DMIT 状态。
- 保存按钮有就近状态提示，设置保存后读取服务端值；重新登录保留尚未保存的表单内容。


### 恢复与故障处理修复

关闭夜间静默时立即尝试恢复原群权限；失败保留恢复状态。开始通知迁移到多条待删除记录，失败按退避时间重试，关闭通知也会继续清理历史记录。验证超时处罚使用持久任务，封禁成功才清除验证状态；重试等待不阻塞普通消息处理，旧验证任务不会处罚已更新的验证状态。后台群列表独立加载并支持手动刷新，其他面板读取失败不会阻断登录。提交已确认但回读失败时明确提示已保存。DMIT 公告备用推送同时保留官方公告按钮和推广购买入口。


### 样本审核与联防纠错

新增样本默认待审核。文字样本归一化后至少六个 Unicode 字符；旧的过短样本不再参与处罚。启用前必须预览固定正常聊天示例，并使用十五分钟有效的预览票据；预览不表示可以覆盖所有误报场景。

只有已加入联防的来源群才触发同步。联防目标群各自使用持久任务，单群失败不会阻挡其他群；后台“联防执行与误封纠错”显示各群状态并允许单群重试。每次操作保存来源群、目标群和命中样本，记录保留九十天。

撤销先停用该次命中样本、取消未执行的关联任务，再按本机器人保存的封禁所有权解封。此前已封禁、后续由本机器人其他处罚覆盖、旧版没有来源记录的情况不会自动解封。Telegram 中直接进行的手动操作无法仅凭此账本完整追溯；已删除消息无法恢复。

DMIT 备用公告首次成功读取只建立基线，后续仅推送新的补货公告 ID，重复或历史公告不再补发。运行状态区分库存页面读取与官方公告备用；官方公告不是当前库存确认。

### 2.5.0 运维与复核完善

- 日报按实际完成的删除、封禁步骤统计，以任务去重，分别显示跨群去重的广告账号数、各群封禁次数、成功误封撤销次数及 OCR 超额跳过数。新版步骤保存完成时间，隔天重试不会再次计入昨日已完成的处罚。
- 日报对每位接收人、每个消息分段持久化发送进度，并固定首次生成的报告内容。北京时间 09:00 后，当天定时任务继续补发未送达的分段；已送达的接收人不重复发送。
- OCR 配额改为从首次识别开始的固定一小时窗口，缓存命中不占额度。选群加载记录后可查看已用、剩余次数和恢复时间；超额跳过写入日志，同一群同一窗口成功提醒后不重复提醒。
- 联防记录每页 50 条，可按群 ID、用户 ID、执行状态（包含撤销失败）筛选；记录更新保留稳定游标，不再只展示最近 100 条。
- 后台增加人工确认案例库；处理记录可填入案例复核表单，只有明确确认分类才会保存。系统移除邮箱、Telegram 用户名、长数字及 HTTP 链接的路径和参数，但不能替代对姓名、地址等信息的人工脱敏。案例保留 90 天、上限 500 条；样本预览分别显示人工确认正常消息的命中和广告案例的命中/遗漏。案例库变更后旧预览票据失效，必须重新预览。

### 2.6.0 备份、审计与规则试运行

- 每 5 分钟检查 Telegram API、Webhook 配置及近期投递错误、各群失败任务/逾期积压、机器人删消息与封禁权限。异常和恢复分别发送一次提醒；提醒未送达会在后续检查补发。未来到期的验证等任务不会被当作逾期积压。此检查运行在 Worker 内，不能替代对 Worker 完全停机的外部监控。
- 后台备份导出各群正在使用的配置（含关键词、域名、群规、验证、静默、知识库等）、广告样本状态、联防名单；不包含密钥、登录会话、试运行历史、封禁账号和待执行任务。每份最多 100 群、1000 样本、500 KB。恢复必须先预览差异，再明确点击确认；预览有效期 15 分钟。恢复前内容保留 7 天，可读取后再次预览恢复。
- 恢复会逐群保存完成进度，失败可通过原确认按钮续作。预览后的修改会阻止旧恢复；续作也检查尚未完成群的配置和全局样本/联防是否变化。跨群恢复不是单个事务，失败时已完成的群保持已恢复状态，审计会记录差异。全局样本/联防阶段使用本地 SQLite 事务。未列入备份的群保持原配置，未列入备份的样本停用，现有样本 ID 保留，避免错连联防纠错记录。
- 已登录后台的修改操作记录开始及完成/失败状态、会话摘要、操作目标和前后差异；界面只显示同一操作的最新状态。保留 90 天、每页 50 条。会话摘要用于区分会话，不是多用户实名认证；记录不含密码、原始会话 Cookie 或机器人密钥。
- 新规则试运行支持本群关键词和黑名单域名，最多 100 条。观察正常审核路径中的正文、隐藏链接及已有 OCR 输出；不增加 OCR 调用，原有过滤仍执行。每条规则按消息去重累计命中，并保留最近 20 个例子；人工核对后可正式启用或停止观察。观察计数不是误报率，仍须人工判断正常/广告。
